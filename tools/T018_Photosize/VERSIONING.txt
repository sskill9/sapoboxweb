版・配布管理（2026-11-08）

正本はtool-config.jsのrelease.versionです。画面・ZIP名（ID-v版.zip）・Gitタグ（小文字ID-v版）をここから生成します。
release.templateVersionは採用したT000の版です。各ツール自身の版とは別です。日付と変更点はrelease.date / release.changesへ記入します。過去の履歴は新しい版番号へ書き換えず、記録のない版は「版番号不明」とします。T000の古い記載例は公開履歴ではありません。

対象版: T000 1.0.0 / T018 1.1.1。
既存のGitタグt018-v1.0.0 / t018-v1.1.0と既存配布ファイルは変更しません。

生成: Python 3.10以上とNode.jsが必要です。信頼したローカル設定だけを入力してください。
python build-release.py --output-dir 新しい候補出力フォルダ
同じソースと同じPython/zlib環境では同じバイト列を生成します。ZIPの日時は固定です。環境を変えると圧縮結果が変わる可能性があるため、公開には一度生成したZIPそのものを使います。
既存ZIPとバイト列が違う場合は上書きせず停止します。未公開候補のやり直しも新しい出力フォルダへ。公開版の変更には版を上げてください。

ファイル一覧はdistribution.filesへ明記します。動的に参照するファイルをdynamicDependencies、必要なライセンスをlicenseFilesにも明記します。新しいツールではすべて更新してください。HTML/CSSとJavaScriptのリテラル参照を照合し、欠落・未列挙・危険なパス・外部実行時依存を拒否します。任意のJavaScript式から生成する依存は静的検査では推測できません。明示リストとコードレビューが必要です。未対応のsrcsetは検査漏れを避けるため拒否します。既存ツールの通常処理は外部ライブラリを読み込みません。

配布コピー: headerLinks.mode=download / downloads.enabled=falseだけを変えます。自身のHTMLへ戻り、再ダウンロード入口を隠します。release.publishedをtrueに偽装しません。published / sameArchiveVerifiedはWEB側の配布リンク公開可否を制御するフラグです。パッケージの審査完了・公開日時を表すものではありません。更新履歴はこのフラグから公開状態を推測せず、日付・版・変更点を表示します。確認範囲と制限はREADMEに記載します。

公開手順:
1. 人力確認と必要な修正を完了し、承認を受けます。その後、READMEの「候補・人力確認待ち」など今回限りの記述を通常配布向けの中立な説明へ更新し、実際の確認結果・残る制限を記録します。公開フラグはfalseのまま、新しい出力フォルダで最終配布ZIPを生成し、SHA-256とソースを保存して凍結します。今回の人力確認用候補ZIPとは別物です。
2. 許可を受けて、そのZIPの同じバイト列をWEBの同じツールフォルダと指定GitタグのReleaseへ配置。
3. 両方から取得したZIPのSHA-256を元ZIPと比較し、記録。
4. 一致と公開状態を確認してからWEB側の設定だけrelease.published=true / sameArchiveVerified=trueへ変更。
   2フラグが両方trueの場合だけ、同一配布の案内と版固定リンクを表示します。
   凍結した最終配布ZIPは再生成・差し替えしません。ZIP内のfalseフラグは非表示の配布リンクの設定値であり、公開状態を利用者に表示する根拠にはしません。
5. 公開済みZIP、SHA-256記録、ソースと旧版を保持し、必要なら旧版へ戻せるようにします。

この生成スクリプトは公開・Git更新・Driveへの保存を実行しません。ブラウザ/file://の再検証は行っていません。自動検査の合格は人力操作・実端末・オフライン動作の保証ではありません。
